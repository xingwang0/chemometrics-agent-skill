# 数据格式契约

本技能的输入是"一张表"：每行一次测量，每列一个变量。所有约定都是为了**让分组键可靠**——
因为分组键错了，后面所有严谨性都白做。

---

## 1. 宽表（推荐，`data.format = "wide"`）

```
sample_id  batch  replicate  protein  moisture  fat  4000   4008   4016  ...
S001       B1     1          14.767   12.3      5.1  0.512  0.509  0.507
S001       B1     2          14.767   12.3      5.1  0.515  0.511  0.508
S002       B1     1           8.046   21.7      2.4  0.498  0.497  0.499
```

| 列类型 | 说明 | 是否进特征矩阵 |
|---|---|---|
| `sample_id` | **分组键**：同一样品（同一材料、同一批次样品、同一受试者）必须同一个值 | 否（被剥离） |
| `batch` | 批次 / 仪器 / 操作者 / 日期（可多列组合，见下） | 否 |
| `replicate` | 同一样品第几次测量（1,2,3…） | 否 |
| 目标列 | 要预测的量（浓度、性能、类别标签） | 否 |
| 特征列 | 数值型，例如波数 / 波长 / 工艺参数 | 是 |

**列名即波数**是强烈推荐的约定：`4000`、`4008`…（或 `4000.0`）。这样
* 画图时自动得到正确的波数轴；
* 波段分组（`interp.band_size`）按列名推断波段中心；
* 不需要额外维护 `wavelength_axis` 的长度一致性（额外的非光谱列不会破坏对齐）。

若列名不是数值（如 `sp_0001`），请务必把 `data.wavelength_axis` 填对，
否则图 F7 的横轴只能用"特征序号"。

## 2. 长表（`data.format = "long"`）

三列式（仪器导出常见）：

```
sample_id  wavenumber  intensity
S001       4000        0.512
S001       4008        0.509
```

配置：

```json
"data": {
  "format": "long",
  "long_cols": {"id": "sample_id", "x": "wavenumber", "y": "intensity"}
}
```

**其它列会自动保留**：除 `long_cols` 指定的 x / y 之外，长表里的每一列（目标值、`batch`、
`replicate`、备注……）都会按 `id` 挂回宽表——仪器导出常常把「一样品一属性」重复写在每一行上。
同一样品多行取值不一致时取首行并给出 `warn`（逐点变化的量，如温度曲线，请先聚合或改名）。

> 1.2.10 及更早版本只保留「样品 ID + 波数列」，目标列在转宽后消失，任何有监督任务都会
> 报 `E-IO-014 目标列不在表头中`。若你手上是旧版产物，请升级后再用长表。

**强制校验**：转宽表后若有任何缺失格，说明各样品波长轴不一致 → 直接报错
`E-IO-007`，不会静默对齐。请先统一定标或做插值后再用长表格式。

> 长表附带进来的非谱列（如水分/脂肪）若留在特征矩阵里，会让 `wavelength_axis` 的点数
> 提示失真、波段分组把它们当成独立波段。建议用 `data.exclude_from_features` 排除。

## 3. 分组键的解析优先级

1. `data.id_col` 显式指定（**最可靠，永远优先用这个**）
2. 命名约定自动识别：`sample_id / sampleid / sample / specimen_id / 样品编号 / 样本编号 / 编号 / 序号`
3. 兜底：对特征列 `round(4)` 后逐行哈希 → `auto_0001…`

第 3 种会在 `audit.md` 里出 ⚠ 警告：**同一材料的多次测量若谱图有肉眼可见差异，
指纹推断会把它们当成不同样品，分组失效**。所以：

> 只要存在重复测量，就必须自己提供 `sample_id`。

什么算"同一个样品"：
* 粉末/液体：同一份试样分装测量 → 同一 `sample_id`
* 同一块材料不同位置打点 → 同一 `sample_id`（若你想研究空间不均性，也可用不同 id，但要意识到此时"抗泄漏"的目标变了）
* 不同合成批次的同名配方 → **不同** `sample_id`，但同一 `batch` 可能也不对——批次应按"会影响谱图的工艺/仪器因素"划分

## 4. 批次列

`batch_col` 可以是单列，也可以先自己合成一列复合键再指定：

```python
df["batch"] = df["仪器"].astype(str) + "|" + df["日期"].astype(str).str[:7]
```

用途只有一个：**留一批次外部验证**（`split.strategy = "loo_batch"` 或 `"holdout_batch"`）。
这是审稿人最认的"真外推"，比任何内部验证都硬。

没有批次列也可以跑，但报告会在 limitations 里自动写"跨批次外推未验证"。

---

## 5. 缺失值

* 目标缺失的行 → **直接剔除**（并在 notes 里记录条数）
* 特征缺失比例 > `data.min_valid_frac`（默认 0.5）的列 → **整列丢弃**
* 剩余零星缺失 → 用列中位数插补，并在 `audit.md` 标注风险

> 中位数插补会低估方差。缺失 > 5% 时，建议改用迭代插补（`IterativeImputer`）
> 并做敏感性分析（插补 vs 删除，结论是否一致）。

`data.na_values` 默认把 `""`、`NA`、`N/A`、`nan`、`null`、`-`、`--` 视为缺失。
如果你的仪器用 `-999` 表示超量程，请显式加进去：`"na_values": ["-999", "..."]`。

## 6. 多目标回归

`task.target` 可以给多列：

```json
"task": {"type": "regression", "target": ["蛋白", "水分", "脂肪"]}
```

管线会**逐目标**独立建模（不共享特征权重），OOF 结果里用 `target` 列区分。
耗时按目标数线性增加。分类任务只支持单目标。

**兄弟目标列一律不进特征矩阵。** 用「蛋白」列去预测「水分」，在真实配方/材料数据里
（蛋白-水分常 |r|>0.7）等于白送一个强特征，R² 会虚高，而审计的通用泄漏检查
（单特征完美预测、近零方差、重复列）识别不出来——它看起来只是个"相关性很好的普通特征"。

两个路径都堵上了：

* 多目标同目录：`roles` 收全部 `task.target`；
* fan-out 子 run：子 run 的 `task.target` 只剩一个，`run_pipeline` 会额外传
  `data.exclude_from_features=[全部目标列]`，`io_data` 再并进角色列。

审计报告里会多一条「目标列未进入特征矩阵」，写明到底剔了哪几列。
若你确实想用兄弟目标当特征（例如水分已知、要预测蛋白），就单独跑单目标：
`--set task.target=["水分"]`，那条路径不会自动排除其它列。

`run_pipeline.py` 会把多目标**拆成独立的子 run**，而不是塞进一个目录：

```
runs/nir_v1/
├── targets_index.json           # 各目标最优模型（并列，不做跨目标排序）
├── targets_summary.md           # 给人看的索引表
└── targets/01_蛋白/  02_水分/    # 各自一套 audit/cv/interp/perm/ad/figures/tables/report
```

为什么必须拆：不同目标的指标尺度（含量 vs 水分）与难度完全不同。
在同一张 `metrics_summary.csv` 里按 R² 全表排序，选出的是"跨目标最强"的模型；
T2 的 CI 也只会按模型建映射，后一个目标会覆盖前一个——两个错误都不会报错。

需要单目录对照时用 `--no-fanout --stages audit,cv`；同一目录跑
interp/perm/ad/report 会在开跑前被 `E-CFG-031` 拒绝（否则要等 CV 白跑完才在报告阶段失败）。
只想建模单个目标时直接写 `--set task.target=["蛋白"]`。

## 7. 常见踩坑

| 现象 | 原因 | 处理 |
|---|---|---|
| `E-IO-014 目标列不在表头` | Excel 有多级表头 / 首行是单位 | 先把表头整理成单行再读 |
| 特征数比预期多 3–5 个 | 成分列、序号列被当成特征 | 加进 `data.drop_cols`，或显式 `feature_cols` |
| 每行都是独立 group | 没提供 `sample_id`，指纹推断未命中 | 补 `sample_id` 列 |
| 分类标签出现 3 类 | 标签里有空格/大小写差异 | 先 `str.strip()` 清洗，或用 `task.label_order` 显式给顺序 |
| 中文列名乱码 | CSV 不是 UTF-8 | 配置 `"encoding": "gb18030"` |
