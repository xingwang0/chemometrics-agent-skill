# 验证方案：分组 / 嵌套 / 重复 / 留一批次

这份文档只回答一个问题：**我该用哪种交叉验证，以及为什么**。
指标公式见 `metrics-and-inference.md`。

---

## 1. 为什么必须分组（本技能的第一原则）

光谱/材料/临床数据几乎必然存在"同一样品测多次"：

```
样品 S001: 测量1, 测量2, 测量3   → 谱图几乎相同，y 完全相同
```

随机 KFold 会把测量1放训练集、测量2放测试集。模型不需要学到任何化学规律，
只要"认出这是 S001"就能答对。R² 会虚高到 0.95+，而换一批新样品立刻崩到 0 以下。

**这不是"稍微乐观"，而是结论完全错误。** 本技能自带一张探针数据集
（`assets/examples/leakage_probe.csv`）来量化这一点：
1-NN 在随机 KFold 下 R²=0.98，在 GroupKFold 下 R²=-1.16。

`selfcheck.py` 把这个对比做成了断言，每次跑都会验证一遍。

## 2. 四种策略怎么选

| 策略 | 适用场景 | 回答的问题 | 代价 |
|---|---|---|---|
| `nested_group`（默认） | 有重复测量，只有一批数据 | "在这批数据的同类新样品上，性能如何" | 中 |
| `loo_batch` | 有 ≥3 个批次/仪器 | "换一批/换台仪器还能用吗" | 高（折数 = 批次数） |
| `holdout_batch` | 已留出独立批次 | "在指定的外部批次上表现如何" | 低 |
| `holdout_random` | 只要快速试跑 | 不推荐用于论文 | 低 |

**推荐组合**：主结果用 `nested_group`，另附一组 `loo_batch` 作为真外推证据。
审稿人看到"跨批次验证"往往就不再纠缠内部验证的细节。

## 3. 嵌套交叉验证（为什么必须）

```
外层（评估）：
  fold1: train 48 样品 | test 12 样品
    └─ 内层（调参）：在 48 样品内部再做 3 折分组 CV
         试 8 组超参 → 选出最优 → 在 48 上重训
    └─ 用最优模型预测 test 12 样品 → 得到"干净"的性能
```

如果不用嵌套，而是"先在全量数据上 5 折 CV 调参，再用同一个 5 折报性能"，
报出去的数字是"在这批数据上挑出来的最好成绩"，乐观偏差通常在 3–10 个 R² 百分点。

> 实现细节：内层没有 `groups` 通道，因此本技能把内层分组划分**展开成显式 split 列表**
> 传给 `GridSearchCV(cv=splits)`。这在数学上等价，且在 sklearn 1.9 下实测稳定。

## 4. 重复交叉验证（为什么报 mean±sd）

一次 5 折划分只用了 5 个特定组合。换一批随机种子，R² 可能差 0.03。
所以用 R 个不同种子各做一次完整外层 CV（本技能默认 R=5）。

**聚合口径（极易出错）**：

```
正确：对每个 repeat 先算 5 折均值 → 得到 R 个均值 → 对这 R 个值算 mean±sd
错误：把 R×5 = 25 个折值直接算 sd
```

后者的 25 个值里有大量相关性（同一批样品反复出现在不同折），当独立样本算会
把 sd 低估 2–3 倍，于是"看起来极其稳定"。本技能在 `metrics.aggregate_repeats`
里强制了这个口径，`selfcheck` 也做了断言。

---

## 5. 折数与样本量

| 独立样品数 | 外层折数 | 说明 |
|---|---|---|
| < 5 | 不建议建模 | 任何性能估计都不可信 |
| 5–9 | 3 | 5 折会出现只有 1–2 个样品的测试折，R² 无意义 |
| 10–30 | 5 | 常规 |
| > 30 | 5 | 可考虑 10 折，但收益递减 |

内层折数：分类任务若最小类样本 < 内层折数，`StratifiedGroupKFold` 会退化，
本技能会自动把内层降到 `min(配置值, 最小类样本数)` 并在 audit 里提示。

**单折 R² 不可解释的情况**：测试折少于 ~10 个样品时，R² 的方差极大（可能为负）。
这时只应看 repeat 级的聚合值，不要引用单折数字。

---

## 6. 伪重复与单位一致性

三个层面必须对齐，否则方差被低估：

1. **重采样单位** = 样品（不是行）→ 本技能的 bootstrap 按 `sample_id` 抽
2. **划分单位** = 样品 → GroupKFold
3. **报告单位** = 样品 → 写"60 个独立样品"，而不是"180 条光谱"

论文里写 "n = 180" 而实际只有 60 个独立样品，是审稿人一眼能看出的问题。

---

## 7. 模型选择的乐观偏差（winner's curse）

同时比较 6 个模型 × 5 条预处理 = 30 个候选，挑最好的报出去，天然偏乐观。

本技能的处理：
* 预处理候选作为**搜索维度**进入内层，与外层评估分离；
* 报告的是"这套协议下的期望性能"，而非"最好的那个数"；
* 模型间差异用配对 bootstrap + 多重比较校正（`cv/comparison.csv`），
  不显著的差异不写成"更优"。

若要更严格：另外留一个完全没参与任何选择的批次做最终检验（`holdout_batch`）。

---

## 8. 配置模板

```json
"split": {
  "strategy": "nested_group",
  "outer": {"n_splits": 5, "shuffle": true},
  "inner": {"n_splits": 3, "shuffle": true},
  "repeats": 5,
  "stratify": true
}
```

留一批次：

```json
"split": {"strategy": "loo_batch", "repeats": 1}
```

（`loo_batch` 下 repeats>1 意义不大，因为划分由批次唯一决定。）
